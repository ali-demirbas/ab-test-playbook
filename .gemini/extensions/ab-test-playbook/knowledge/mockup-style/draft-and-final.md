# Draft, conditional and final card

Read for the UNVERIFIED preview (render_check exit 3), a share image, an overview or a `--check`, or a question about a ribbon or a build (the core: `knowledge/mockup-style.md`; the steps: `ab-test-card` → Delivery pipeline; a quick draft: `fast-mode.md`).

`build_card.py` writes a card in two passes (`knowledge/methodology.md` → Quality gates); only the final or conditional card is delivered.

- **Draft** (`--draft`): needs the scenario-critic stamp matching the current record. It is the final card plus a calm slate pill at the top right, “Önizleme · görsel kontrol yapılmadı” / “Preview · not visually checked”, that changes nothing in the layout, and the meta tag `<meta name="abtest-status" content="draft">`; it carries no fingerprint. The build prints the draft and manifest paths and the `--stamp` command. A draft is for the mockup reviewer only: on PASS it runs `build_card.py --template … --scenario <record> --stamp <draft.html>`, which writes nothing, refuses a draft or manifest the record no longer builds, and prints the stamp JSON that goes into `review.mockup_reviewer`.
- **Conditional card** (koşullu kart, never called final): a record with at least one critical assumption builds a conditional card, never a final one, with the “KOŞULLU · doğrulama gerekli” / “CONDITIONAL · needs verification” ribbon (a filled amber pill, white 14px text, top left above the title, readable in a thumbnail) and `<meta name="abtest-status" content="conditional">`, the build summary saying “conditional card (not implementation-ready)”; its draft shows both ribbons (the draft one top right) and its first `abtest-status` says `draft`, and it still needs both stamps. When the user confirms, the assumption leaves the record, which goes back through the critic, a new draft and the mockup review, and only then is the card final, with no ribbon.
- **Manifest** (`<out>.manifest.json`, written with the draft): every difference between A and B inside the rings, one item each. The reviewer confirms each is the declared variable or a labelled linked difference; any other item is a FIX, even when the code found nothing wrong.
- **Final** (no `--draft`): needs both stamps, the critic's matching the record and the mockup reviewer's matching the card about to be written (its bytes, `card.mockup_basis` and the manifest); no draft ribbon or draft meta tags. A refused build writes nothing: a file already at `--out` stays as it was, and the message says so. The build prints the final card's fingerprint; `--check <card.html>` confirms later that a delivered file is byte for byte that reviewed card.

## The UNVERIFIED preview

When the visual check was unavailable (exit 3, verdict `UNVERIFIED`), the draft is given as a preview labelled UNVERIFIED in chat, never called final (its ribbon says "Önizleme · görsel kontrol yapılmadı" / "Preview · not visually checked"). The chat line that goes with it is calm and says three things once per turn, in the user's language, and nothing more: what this is, that it has not been visually checked yet, and the one-time command that gets checked cards from now on. EN: "This is a preview of your card (UNVERIFIED): the test plan is reviewed, but the drawing has not been visually checked yet, because the visual check is not installed on this computer. To get fully checked cards from now on, run this once in a terminal: `npm i --prefix ~/.abtest-visual playwright && npx --prefix ~/.abtest-visual playwright install chromium`. Then tell me and I will check and finish this same card." TR: "Bu, kartınızın bir önizlemesi (UNVERIFIED): test planı incelendi, ama çizim henüz görsel olarak kontrol edilmedi, çünkü görsel kontrol bu bilgisayarda kurulu değil. Bundan sonra tam kontrol edilmiş kart almak için terminalde bir kez şunu çalıştırın: `npm i --prefix ~/.abtest-visual playwright && npx --prefix ~/.abtest-visual playwright install chromium`. Sonra bana haber verin, aynı kartı kontrol edip tamamlayayım." No "error", "failed" or "warning" wording: nothing broke, one check is pending. Where nothing can be installed (no terminal, a hosted chat), leave the command out and say the visual check is not available in this environment. Once it is installed the same draft is checked and finished from step 4. The final build still refuses without a mockup PASS stamp (code); that no PASS is given without a render is a review rule (process).

## On request

`--share` on the final build also writes `<card>.share.html` and its PNG: 1200 × 630, the usual link-preview size of chat apps and social posts, the same mockups with the title larger (phones beside the title, desktop frames under it); only a final build writes it. `build_card.py --overview <out.html> <card.html>…` writes one page with a turn's delivered cards as thumbnails and titles, each linking to its card; a draft is refused. Both only when the user asks: `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/build_card.py --share --template ${CLAUDE_PLUGIN_ROOT}/templates/scenario-card.html --scenario <record.json> --out abtest-card-<slug>.html` (the final build with `--share`) and `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/build_card.py --overview abtest-overview.html <card.html> …`. Later, `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/build_card.py --template ${CLAUDE_PLUGIN_ROOT}/templates/scenario-card.html --scenario <record.json> --check <card.html>` confirms that a delivered file is byte for byte the reviewed card.
