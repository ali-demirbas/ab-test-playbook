Claude Code plugin

ab-test-playbook

An A/B test engine for Claude Code. It suggests test scenarios from a curated archive, designs them for your page against a written methodology, audits plans you already have, and renders every scenario as a single-file HTML card.

What a scenario card looks like

Rendered below with no install and no build step: this is the real output of scripts/build_card.py run against a sample record, not a mockup of one.

The test's question, then Variant A and Variant B side by side, large, with the changed element ringed in red and named in a few words. That is all a card shows: the record behind it (the problem, the mechanism, the primary KPI, the guardrail, evidence and priority) stays in the scenario JSON. Open full size. The same card on other screen types: desktop product page · app home screen · demo-request form.

What makes it opinionated

  • One variable. A variant pair changes exactly one thing. If you insist on more, the output says the result cannot be attributed.
  • One primary KPI, always a guardrail. Five metrics of equal weight is not a measurement plan. Every scenario names the metric that decides, and at least one that must not break.
  • No dark patterns, and protections are not test subjects. Fake scarcity, hidden totals and uncloseable modals are refused. So is treating bot checks, identity verification or legal consent steps as friction to remove.
  • Evidence is labelled. Every proposal states whether it rests on your own data, an archive pattern (a curated idea, not a test result), a sector observation, or intuition — and says so when it is weak.
  • No statistics. It proposes, designs, audits and visualizes tests; sample size, duration, significance and the winner come from your testing tool's own reporting, never from a guess.

Install

# in Claude Code: add the marketplace, then install the plugin
/plugin marketplace add ali-demirbas/ab-test-playbook
/plugin install ab-test-playbook@ab-test-playbook

Then, inside Claude Code: /ab-test suggest, /ab-test design, /ab-test audit, /ab-test card. A bare /ab-test shows a short menu with one example prompt for each.

Skills only, limited: npx skills add ali-demirbas/ab-test-playbook --all copies the five skill instructions but not the binding rules, the scenario archive, the scripts or the review agents, so archive suggestions, scenario validation and card rendering do not work. Use the plugin install above for the full engine. Requires python3 3.9 or newer on PATH; the scripts use the standard library only.

What is inside

  • 221 curated scenarios across journey stages (e-commerce, mobile app, SaaS, and regulated finance, insurance and pension flows), each already carrying the three boxes.
  • Short proposals. At most three strong ones per turn, each a compact record (the problem, a one-sentence mechanism, the variable, the primary KPI, the guardrail, evidence and priority) with a card that shows only the comparison; chat shows a title and one tag line, and the three boxes come on request.
  • A plan audit — confounds, a proxy primary, mismatched denominators, guardrails that measure nothing, missing compliance or accessibility gates and dark patterns, caught before the test takes traffic.
  • Adversarial review — a methodology critic reads every generated scenario, and a mockup reviewer checks the two variants differ in exactly one thing, before anything reaches you.
  • Gated delivery — code refuses what it can check (a difference outside the ring, a changed number, an added button without accessibility criteria, a revenue win that could hide user harm), and the final card builds only with both reviewers' stamps matching exactly what they reviewed.
  • A portable schema — a test definition independent of any experimentation platform.
