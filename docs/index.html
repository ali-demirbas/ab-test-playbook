A/B Test Builder

Turn a screenshot of your page into single-variable A/B test plans, each with one primary KPI and one guardrail (a metric that must not get worse), reviewed by two agents and drawn as a side-by-side card.

Does moving the coupon field behind an “I have a discount code” link increase revenue?

A real card, as the plugin draws it for every test: the question, Variant A and Variant B, and the one change ringed and named. Open the card itself: English · Türkçe. The plan behind it (the problem, the reason it should work, the primary KPI and the guardrail) stays in the chat and the scenario file.

First card in 3 steps

Requirements: Claude Code and Python 3.9 or newer. Node 18 or newer and Playwright are needed only for the final visual check (step 2).

  1. Install the plugin. Type these in Claude Code: 
    /plugin marketplace add ali-demirbas/ab-test-playbook
/plugin install ab-test-playbook@ab-test-playbook
    A/B Test Builder is the display name; the plugin installs as ab-test-playbook.
  2. Turn on the visual check (optional, recommended). Run this once in a terminal. It installs Playwright and Chromium outside your projects: 
    npm i --prefix ~/.abtest-visual playwright && npx --prefix ~/.abtest-visual playwright install chromium
    Skip it and you still get your cards, as previews marked “not visually checked”. Run it later and the same cards get checked and finished.
  3. Ask for a card. Paste a screenshot of your page and type: 
    /ab-test design a test for this page
    No screenshot at hand? /ab-test suggest tests for my checkout page starts from an archive of 217 curated scenarios. A bare /ab-test shows a short menu.

Codex, Gemini CLI, claude.ai, updating and troubleshooting: install guide. The skills-only route (npx skills add) copies the instructions without the rules, the archive and the scripts, so use the plugin install above.

What makes it opinionated

  • One variable. A variant pair changes exactly one thing. If you insist on more, the output says the result cannot be attributed.
  • One primary KPI, always a guardrail. Five metrics of equal weight is not a measurement plan. Every scenario names the metric that decides, and at least one that must not break.
  • No dark patterns, and protections are not test subjects. Fake scarcity, hidden totals and uncloseable modals are refused. So is treating bot checks, identity verification or legal consent steps as friction to remove.
  • Evidence is labelled. Every proposal states whether it rests on your own data, an archive pattern (a curated idea, not a test result), a sector observation, or intuition, and says so when it is weak.
  • Two reviews before delivery. One agent challenges the test plan, another checks that the two drawn variants differ in exactly one thing. A card is final only with both, plus the visual check from step 2.
  • No statistics. It proposes, designs, audits and visualizes tests; sample size, duration, significance and the winner come from your testing tool's own reporting, never from a guess.
